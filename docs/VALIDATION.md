# VALIDATION

## Decisions
- Scope: local Windows L81 trial, not a public production release or game-compatibility claim. SDK 10.0.303, WPF win-x64; Core/tests remain portable. No new package dependencies. Official checkout 7.0.1/setup-dotnet 6.0.0 are SHA-pinned (Node 24), replacing the CI-observed deprecated Node 20 action runtimes.
- Tesseract 5.2.0; official English fast model pinned by revision and SHA256 in `scripts/setup-model.ps1` and `src/Sitrep.Desktop/tessdata/README.md`. No runtime downloads.
- Apollyon L81 revision `e8d1ee9ceb07fe9ec4923b7b55e836f8b3bb3e05`: 132–684 m, linear interpolation, no extrapolation/terrain correction. All 84 upstream samples and limits independently compared with the local profile: exact match. See `src/Sitrep.Core/Data/PROVENANCE.md` for rights limitations.
- Always live, guarded (BUILD_SPEC revision 3; no permission or Gate E claim): no Enable/F10 barrier; capture is gated only by the foreground window's executable matching `GameProcessName` (default `wardogs`, case-insensitive substring so `*-Win64-Shipping` also matches), the optional `ForegroundTitleContains` fallback, or desktop test mode. Ctrl+MMB origin, Shift+MMB target, F9 clear; F8/F7 remain aliases; MMB state is polled only for the chord edge and a plain middle click never triggers capture. Because input is observed globally, F9 acts only while the attached game window or SITREP's own control window is in the foreground (there is no Clear button); F9 typed into an unrelated application is ignored. Foreground polling binds one HWND; loss hides the overlay and invalidates targets, closure clears origin. Focus changes reseed input; changing the game identity or test mode clears window attachment/origin.
- Map guard: `RoiBuilder.GetCenteredMapRegion` = centered square of `0.611 × client height` (880 px at 2560×1440, matching the reference screenshots' 840…1719 horizontal span). Clicks outside reject pre-capture as `OUTSIDE MAP AREA`, mirroring `MOVED` semantics (origin attempt clears origin; target attempt keeps origin). Skipped in desktop test mode and when client bounds are unavailable; this does not bypass the capture backend's required client/monitor bounds or the foreground/OCR gates. **Calibration is from screenshots only, not yet confirmed in game; windowed/letterboxed layouts may need the fraction adjusted.**
- Single control window (resizable, optional always-on-top) with auto-saved settings; `SettingsWindow` removed. Minimize hides only after successful native tray registration (`Shell_NotifyIcon`, no WinForms), otherwise the taskbar remains available. `TaskbarCreated` re-registers after Explorer restarts; failure reveals a hidden control window. Registration is idempotent, menu instances are closed on replacement/shutdown, and hooks/callbacks are detached before disposing the icon. Overlay owns lock/unlock window styles only; the control window persists `OverlayLeft/Top` on lock, so diagnostics never write the user's config. `OverlayLeft/Top` are nullable (`null` = default top-right placement) so negative coordinates from monitors left of / above the primary round-trip intact; the legacy `-1/-1` sentinel written by earlier builds migrates to `null` on load. `Unlock()` creates the overlay HWND (`WindowInteropHelper.EnsureHandle`) before changing styles, so unlocking before the overlay was ever shown no longer throws `Win32Exception` 1400. Process identity uses one retained safe handle with query-limited-information + synchronization rights (no memory access). Cache hits require a zero-time wait to confirm that exact process is still alive; PID reuse reopens/requeries instead of reusing a stale name. Denied lookups, and identities that are already dead (or whose liveness wait fails on the granted handle) immediately after opening, return no identity, are disposed, and retry after 1 s, not at input rate. Handles are disposed on replacement/shutdown. The separate status-only process scan stays at 2 s, skips enumeration while a matching process is foreground or test mode is enabled, and tolerates process-exit races. Case-insensitive basename substring and optional title-fallback semantics are unchanged.
- Dedicated input sampling thread (~10 ms high-bit polling, no hooks/raw input/synthesis) freezes modifiers, cursor, foreground HWND and event time before UI callbacks. A 64-gesture mailbox survives synchronous dispatcher capture; overflow invalidates work rather than building an unbounded backlog. Plain MMB and Ctrl+Shift+MMB are ignored; adding a modifier while MMB is held does not trigger. F8/F7 aliases coalesce with matching chords, simultaneous origin/target chooses origin, F9 wins its sample and clears the backlog. Disable/focus changes reseed and invalidate epochs; a sampled alt-tab-away/back cannot resurrect pending OCR. Snapshot on the UI dispatcher at the frozen anchor/ROI, then one 50 ms retry before OCR. Reject moved/missing cursor, >500 ms input/retry delay, clipping, own-window overlap, and disagreeing valid recipes/snapshots. Sampling still cannot guarantee detecting presses/focus changes entirely between samples. One OCR worker, at most one replaceable pending item; sampler and OCR worker drain before disposal.
- Debug diagnostics: off by default; at most **50 complete records (100 files)** under local app data, one PNG and matching JSON per snapshot. Timestamp + GUID names avoid collisions even for both snapshots of the same request. A per-directory named mutex serializes same-session application instances, bounded to a 2 s acquisition wait. Staged files publish only after both writes finish, failed writes roll back, and successful saves prune whole records and repair orphan/staging remnants. Locked/unwritable paths remain best effort (repair deferred until writable); no crash-atomic two-file filesystem guarantee or upload/telemetry.
